# V7 vision architecture — design only

V6.2 contains **no image input, screenshot API, file-reading native command, recurring screen observation, OCR or active-window inspection**. This is a deferred design, not an implementation claim.

First gate: owner must certify V6.2 native Windows skin, frame pacing, cancellation, model capability metadata and one-model residency on RTX 3050 8 GB. Only then implement the separate manual-image trial: select one PNG/JPEG, decode and verify actual dimensions, maximum 5 MB source / 4 MP decoded image, strip metadata and resize in memory. Show preview plus explicit Analyze consent. Encode only that image with the installed API's `messages[].images` base64 protocol; Rust validates signature, encoding, pixel budget and byte bounds again, denies unknown fields/paths/URLs, and rechecks actual vision capability. Use only the chosen locally installed vision model; no image or implicit image summary may enter Llama/history/diagnostics/storage. Cancel, Clear Image and disposal release buffers and revoke object URLs. The fallback is an explicitly separate text conversation and must say no image was analyzed.

Desktop capture requires a later independent consent gate. Use a user-selected window/source, visible capture indicator, timeboxed consent, explicit capture action and zero capture when permission is off. No continuous monitoring by default, hidden window enumeration/history, screenshots in overlay events, global keys/pointer collection or autonomous OS actions. Permission revocation, minimization, source closing, app exit and timeout must stop capture. Any recurring observation needs its own owner-approved retention/rate policy and native tests.

Use the existing Workspace LocalConversation session and reaction coordinator, plus a narrowly scoped native capture owner if separately authorized. Overlay consumes only allowlisted visual cues. Never add a competing BehaviorController, renderer, inference scheduler or unbounded event bus. Verify privacy with native permission tests, payload rejection, cancellation races, zero-capture probes, memory/lifecycle checks and owner GPU measurements. Ollama /api/show and actual installed version determine capability/format; model names alone do not certify vision.

References checked for V6.2 contract: https://docs.ollama.com/api/chat , https://docs.ollama.com/api/generate , https://docs.ollama.com/api/ps . Local installed-version and actual vision acceptance were NOT RUN in Work.
